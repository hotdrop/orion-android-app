# ORION UI Experience

## 世界観を機能へ結び付ける

- `README.md` の「近未来のAI研究施設」をデザイン判断の正本にする。
- Cyberpunk、Sci-Fi、Tactical UI、Hologram、HUD、Terminal、Intelligence、Mission Controlを一貫した視覚言語として扱う。
- 装飾を状態、階層、進行、警告、操作結果の表現へ結び付ける。意味を持たない演出を増やす場合も、情報の読解や操作を妨げない。
- Material 3は土台や相互運用に必要な範囲で使い、既定コンポーネントの見た目にORIONを従属させない。
- 色、タイポグラフィ、間隔、形状、線、発光、モーション、サウンドを再利用可能なトークンまたは共通プリミティブへ集約する。
- 各コンポーネントに通常、操作中、選択、無効、エラーなど必要な状態表現を持たせる。

## Composeを安定させる

- 画面Composableへ状態とイベントを渡し、データ取得、保存、認証を直接実行しない。
- 不変データと安定したコールバックを使い、不要な再コンポーズを抑える。
- Canvas、Path、Brush、文字列整形などフレームごとの生成を避け、計算結果を適切に記憶する。
- アニメーション対象を必要なプロパティへ限定し、無関係な画面全体を再描画しない。
- 既存要素への単純なalpha、移動、拡縮は実行環境で滑らかさを観察し、ジャンクが見つからなければ正式なフレーム計測を必須にしない。
- Canvasの描画範囲拡大、ブラー、多層発光、無限アニメーション、画面全体の再描画を追加する場合、または観察時にジャンクを検知した場合は、実機またはエミュレータでフレームを計測する。
- 60FPSを品質条件として扱い、恒常的なジャンクを演出の代償にしない。計測していない変更を「60FPS確認済み」と報告しない。

## モーション・音・触覚を設計する

- モーションで画面遷移、データ到着、処理進行、成功、警告の因果関係を伝える。
- 起動演出や継続アニメーションが頻繁な再訪を遅らせる場合は、短縮、スキップ、停止、または軽量表示へ移れる経路を用意する。
- サウンドと触覚は操作結果に同期させ、短時間の重複再生やライフサイクル外の再生を防ぐ。
- サウンドや強い演出が継続・反復する場合は、システム設定で十分かを確認し、不十分な場合だけアプリ内のミュートや軽量表示を設計する。
- システムのアニメーション無効化や縮小設定を尊重し、情報や操作をアニメーションだけに依存させない。

## 読めて操作できる状態を保つ

- 発光や低コントラストを雰囲気だけで選ばず、主要テキスト、操作対象、エラーを判別可能にする。
- タッチ領域、セマンティクス、フォーカス順、スクリーンリーダー用ラベルを壊さない。
- 長文、文字サイズ拡大、空、読み込み、エラー、オフラインの状態でも主要操作へ到達できるようにする。

## UI変更を確認する

- 新規作成または大きく変更する再利用可能なComposableと主要画面にPreviewを用意し、代表状態を個別に表示する。小さな変更では既存Previewを利用し、Preview新設だけを目的にスコープを広げない。
- 通常、空、読み込み、エラー、長文、ユーザー編集済みなど変更に関係する状態を確認する。
- 動きや描画性能を変更した場合はPreviewだけで完了せず、利用可能な実行環境で遷移、連打、スクロール、復帰を確認する。環境がない場合は未確認のリスクとして報告する。
- `.skills/android-quality-gates/SKILL.md` から変更リスクに合う検証を選ぶ。
